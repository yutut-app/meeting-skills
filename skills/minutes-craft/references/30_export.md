# 作業スペースと渡す形

## 作業スペース

### なぜスキルフォルダに置かないか

**このスキルのリポジトリは公開されている。** 議事録には取引先の社名、担当者名、
単価、不良の内容が入る。スキルフォルダに置くと GitHub に出る。
しかも **git の履歴に残るので、後から消しても取り除けない。**

### 置き場所 ★環境の決めごと

| 置くもの | 場所 | 越えて効くか / push 可か |
|---|---|---|
| 議事録、素材、中間物 | `<WS>/<領域>/YYMMDD_PJ名/` | いいえ / — |
| **取引先ごとの議事録フォーマット** | `<WS>/<領域>/formats/` | はい / **いいえ**（取引先名を含む） |
| **分野・取引先ごとの用語集** | `<WS>/<領域>/glossary.md` | はい / **いいえ**（取引先名と分野が分かる） |
| スキル本体、雛形、台帳 | `<SKILL_REPO>/` | はい / はい |

`<WS>` と `<領域>` の具体値は本文に書かない。**`scripts/ws-path.sh` が返す。**
絶対パスを本文と参照ファイルに直接書くと、置き場所を変えたときに書き換えが漏れる。
出所を1箇所にしておけば漏れようがない。

### 使い方

```bash
# 案件ディレクトリ（その案件だけのもの）
WS=$(scripts/ws-path.sh "261008_○○株式会社-上期打合せ") || exit 1

# 領域直下（PJ を越えて効くもの。formats/ と glossary.md がここ）
DOMAIN=$(scripts/ws-path.sh --domain-root) || exit 1
```

**この2つがパスの出所。** 本文と参照ファイルに絶対パスを直接書かない。
書くと、置き場所を変えたときに書き換えが漏れる。

### formats/ と glossary.md の使い分け

| ファイル | 中身 | 誰が増やすか |
|---|---|---|
| `formats/<取引先>.md` | その取引先の議事録の章立て・列・呼称 | 書式を受け取ったとき、または過去の議事録から読み取ったとき |
| `glossary.md` | 崩れた語と確定した正しい表記（`15_terms.md` 5節） | 崩れ候補の合否を利用者が答えたとき |

**どちらも、確定したものだけを置く。** 推定や未確認を混ぜると、
次の案件で未確定のものを確定済みとして引いてしまう。

**失敗したら止める。** 既定の場所へ落とさない。
落とすと書けたことになって、どこに書いたか分からないまま進む。

### PJ名の付け方 ★環境の決めごと

`YYMMDD_PJ名`。`YY` は西暦下2桁、`MM` `DD` はゼロ埋め、区切りはアンダースコア1つ。
PJ名は日本語でよい。語を区切るならハイフン。

**同じ取引先と複数回会議をするなら、日付で分かれるので同じ PJ名を使い回してよい。**
使い回すかは、**その会議が独立した案件か、継続した案件かで決める。**

| 状況 | どうするか |
|---|---|
| 同じ論点を継続して議論している | 同じ PJ ディレクトリに `minutes-YYMMDD.md` として足す |
| 別の論点の会議 | 新しい PJ ディレクトリを作る |

### ディレクトリの中身

```
<WS>/<領域>/261008_○○株式会社-上期打合せ/
├── README.md          案件の宣言（開始日、使うスキル、目的）
├── source/            受け取った素材（文字起こし、メモ）。原本を書き換えない
├── minutes.md         議事録本体
└── review.md          検査の結果表
```

**`source/` の原本を書き換えない。** 書き換えると、議事録と素材を突き合わせられなくなる。
誤変換の修正も原本には入れず、議事録の側に「要確認」として書く。

## 渡す形

### 既定は Markdown

| 渡すもの | 既定 | 誰が受け取り、何に使うか |
|---|---|---|
| `minutes.md` | **常に作る** | 利用者本人。社内共有、wiki やチャットに貼る |
| `minutes.docx` | 要求されたときだけ | 相手先。そのまま送付・提出する |
| `actions.xlsx` | 要求されたときだけ | 利用者と相手先。宿題の進捗を更新していく |
| 整理前の発言リスト | **渡さない** | 作業用。`<WS>` に残すだけ |

**中間物を渡さない。** 作業用の構造は受け取る側には重く、
どれが成果物か分からなくなる。渡すなら理由を述べる。

### docx へ渡すとき

| 渡すもの | 内容 |
|---|---|
| 入力 | 確定した `minutes.md`（検査を通したもの） |
| 出力先 | `<WS>/<領域>/<PJ>/minutes.docx` |
| 指定 | 表はネイティブの表にする。6節「要確認」は**相手先へ出す版から外す** |

**「要確認」の節を相手先に出さない。** あれは自社内の確認用で、
相手に見せると「決まっていないことを確認している」と読まれ、交渉上の材料になる。

ただし**外すのは6節だけ。** 本文の各表に付いている「区分」列と「不明」の値は残す。
**未決を未決として相手に示すことが、言った言わないを防ぐ。**
区分まで消すと、全部が合意済みに見える版が相手の手元に残る。

### xlsx へ渡すとき

**Excel にするのは5節「宿題」だけ。** 議事録本文を Excel に入れない。
本文は読み物で、Excel は更新するもの。性質が違うものを同じシートに置くと、
更新のたびに本文が壊れる。

| 列 | 内容 |
|---|---|
| # | 議事録の宿題番号と対応させる |
| 内容 | 宿題の内容 |
| 担当 | 自社／相手先／未定 |
| 期限 | 日付、または「不明」 |
| 区分 | 決定／未決／要確認／不明 |
| 状態 | 未着手／進行中／完了（**Excel 側で更新する列。議事録には無い**） |
| 更新日 | 最終更新 |

**議事録本文も Excel にしてほしいと頼まれたら、一度確認する。**
本文を Excel に入れると、次の会議で追記したときに表が崩れ、
**どの版が正しいか分からなくなる。** それでも必要と言われたら作る。

### 委譲の作法

**docx・xlsx の作り方をここに書かない。** 公式スキルが持っている機能であり、
2箇所に書くと片方だけ古くなって食い違う。

渡すのは、確定した md と出力先のパスと上の指定だけ。
**委譲先が同じ機械で動くことを確かめる。** `docx` `xlsx` スキルが無い環境では
md のまま渡し、変換できないと報告する。黙って自分で書こうとしない。
