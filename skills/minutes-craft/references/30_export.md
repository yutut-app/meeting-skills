# 作業スペースと渡す形

## 作業スペース

### 置き場所

**議事録と素材はスキルフォルダに置かない。** スキルフォルダは手順を置く場所で、
案件の記録を置く場所ではない。混ぜると、案件が増えるほど手順が埋もれる。

| 置くもの | 場所 | 案件を越えて効くか |
|---|---|---|
| 議事録、素材、中間物 | `<WS>/<領域>/YYMMDD_PJ名/` | いいえ |
| 相手先ごとの議事録フォーマット | `<WS>/<領域>/formats/` | はい |
| 分野ごとの用語集 | `<WS>/<領域>/glossary.md` | はい |
| スキル本体、雛形 | スキルフォルダ | はい |

**`<WS>` と `<領域>` の具体値を本文に書かない。`scripts/ws-path.sh` が返す。**
書くと、置き場所を変えたときに書き換えが漏れる。出所を1箇所にしておけば漏れようがない。

### 使い方

**スキルディレクトリへ `cd` してから呼ぶ。**
**作業ディレクトリは呼び出しごとに戻るため、`cd` を省くと相対パスが外れる。**

```bash
SKILL_DIR=<この SKILL.md があるディレクトリの絶対パス>
cd "$SKILL_DIR" || exit 1

# 案件ディレクトリ（その案件だけのもの）
WS=$(./scripts/ws-path.sh "261008_○○株式会社-上期打合せ") || exit 1

# 領域直下（案件を越えて効くもの。formats/ と glossary.md がここ）
DOMAIN=$(./scripts/ws-path.sh --domain-root) || exit 1
```

**この2つがパスの出所。** 本文と参照ファイルに**作業スペースの**絶対パスを書かない。
`SKILL_DIR` はスキル自身の位置で、作業スペースの置き場所とは別のもの。

**作業スペースの根は、環境変数 `MINUTES_WS_ROOT` か、
設定ファイル `~/.config/minutes-craft/ws-root` の1行目で決まる。**
どちらも無ければスクリプトが止まる。**既定の場所へ落とさない。**
落とすと書けたことになって、どこに書いたか分からないまま進む。

**設定ファイルを見るのは、環境変数が届かない場合があるため。**
対話していないシェルでは、シェルの設定ファイルが読まれないことがある。

### formats/ と glossary.md の使い分け

| ファイル | 中身 | 誰が増やすか |
|---|---|---|
| `formats/<相手先>.md` | その相手先の議事録の章立て・列・呼称 | 書式を受け取ったとき、または過去の議事録から読み取ったとき |
| `glossary.md` | 崩れた語と確定した正しい表記（`15_terms.md` 5節） | 崩れ候補の合否を利用者が答えたとき |

**どちらも、確定したものだけを置く。** 推定や未確認を混ぜると、
次の案件で未確定のものを確定済みとして引いてしまう。

### PJ名の付け方

`YYMMDD_PJ名`。`YY` は西暦下2桁、`MM` `DD` はゼロ埋め、区切りはアンダースコア1つ。
PJ名は日本語でよい。語を区切るならハイフン。

**同じ相手先と複数回会議をするなら、日付で分かれるので同じ PJ名を使い回してよい。**
使い回すかは、**その会議が独立した案件か、継続した案件かで決める。**

| 状況 | どうするか |
|---|---|
| 同じ論点を継続して議論している | 同じ PJ ディレクトリに `minutes-YYMMDD.md` として足す |
| 別の論点の会議 | 新しい PJ ディレクトリを作る |

### ディレクトリの中身

```
<WS>/<領域>/261008_○○株式会社-上期打合せ/
├── README.md          案件の宣言（開始日、使うスキル、目的）
├── source/            受け取った素材（文字起こし、メモ）。原本を書き換えない
├── minutes.md         議事録本体
└── review.md          検査の結果表
```

**`source/` の原本を書き換えない。** 書き換えると、議事録と素材を突き合わせられなくなる。
誤変換の修正も原本には入れず、議事録の側に「要確認」として書く。

## 渡す形

### 出力形式は案件の決めごと

**既定を1つに固定しない。** md・Word・Excel のどれもありうる。
形式は `SKILL.md` 手順1で確定する。既定は**既存書式の形式に従い、無ければ md**。

| 渡すもの | いつ作るか | 誰が受け取り、何に使うか |
|---|---|---|
| 議事録（決めた形式） | **常に作る** | 社内。次の段取りの確認に使う |
| 先方版 | 相手先へ出すとき | 相手先。**載せる範囲は決めごと**（既定は決定事項と確認事項） |
| 確認事項の進捗管理表（xlsx） | 要求されたときだけ | 更新していく |
| 整理前の発言リスト | **渡さない** | 作業用。作業スペースに残すだけ |

**中間物を渡さない。** 作業用の構造は受け取る側には重く、
どれが成果物か分からなくなる。渡すなら理由を述べる。

**議事録の中身は形式によらず同じ。** 形式で変わるのは体裁だけで、
**節の構成や区分を形式に合わせて削らない。**

### 形式ごとの体裁

**選んだ形式の行だけを読む。** 他の形式の条項を当てない。

| 形式 | 体裁 |
|---|---|
| **md** | 社内共有・貼り付け用。表はそのまま。区切り線は HTML コメントで書く |
| **Word** | 相手先提出用。表はネイティブの表。`docx` スキルへ委譲 |
| **Excel** | 下記の条項に従う。`xlsx` スキルへ委譲 |

#### Excel のときの体裁

**印刷より、画面で見やすいことを優先する。**

| 守ること | 外すとどうなるか |
|---|---|
| **枠線を揃える。**行を複製して線種が混ざらないようにする | 項目の区切りが読めなくなる |
| **項目の区切りが分かる線にする** | どこまでが1項目か分からない |
| **決定事項の行分けは、セルを分ける。**セル内改行にしない | 並べ替えと絞り込みが効かなくなる |
| **図や表は右側に並べる。**下に長くしない | 縦に伸びて全体が一画面に入らない |

**セル内改行にしない理由を外さない。** 見た目は同じでも、
セル内改行にすると**1行が複数の内容を持つことになり、1行1内容が崩れる。**

- **行き過ぎると:** 体裁を整えるために内容を削る。
  **列や行を減らして収めない。**収まらないなら表を分ける

### docx へ渡すとき

| 渡すもの | 内容 |
|---|---|
| 入力 | 確定した `minutes.md`（検査を通したもの） |
| 出力先 | `<WS>/<領域>/<PJ>/minutes.docx` |
| 指定 | 表はネイティブの表にする。**社内用の区切り線より下を外す**（既定では3〜6節） |

**社内用を相手先に出さない。** 要確認は自社内の確認用で、
相手に見せると「決まっていないことを確認している」と読まれ、交渉上の材料になる。

ただし**外すのは社内用の部分だけ。** 1〜2節の「区分」列と「不明」の値は残す。
**握っていないものを握っていないと示すことが、後の食い違いを防ぐ。**
区分まで消すと、全部が合意済みに見える版が相手の手元に残る。

**載せる範囲が決めごとで変わる。** 相手先が議事も求めるなら載せる。
**既定を固定して、言われていない相手先にも「決定事項と確認事項のみ」を当てない。**

### xlsx へ渡すとき

**進捗管理表にするのは2節「確認事項」だけ。** 議事録そのものを進捗管理表にしない。
議事録は会議ごとに確定するもので、進捗管理表は更新していくもの。
同じシートに置くと、更新のたびに議事録が書き換わって版が分からなくなる。

**議事録自体を Excel 形式で作ることとは別の話。** 形式が Excel の案件では、
議事録は議事録として作り、進捗管理表は要求されたときに別途作る。

| 列 | 内容 |
|---|---|
| # | 議事録の確認事項の番号と対応させる |
| 内容 | 決めること |
| 担当 | 自社／相手先／未定 |
| 期限 | 日付、または「不明」 |
| 区分 | 決定／未決／要確認／不明 |
| 状態 | 未着手／進行中／完了（**Excel 側で更新する列。議事録には無い**） |
| 更新日 | 最終更新 |

**架空のサンプル行を入れない。** 記入例として現実的な値の行を求める委譲先があるが、
**議事録と件数が食い違い、どれが実際の確認事項か分からなくなる。**
記入方法は凡例かセルのコメントで示す。これは「素材に無いことを書かない」の一部で、
**委譲先の作法より優先する。**

**議事録本文も Excel にしてほしいと頼まれたら、一度確認する。**
本文を Excel に入れると、次の会議で追記したときに表が崩れ、
**どの版が正しいか分からなくなる。** それでも必要と言われたら作る。

### 委譲の作法

**docx・xlsx の作り方をここに書かない。** 公式スキルが持っている機能であり、
2箇所に書くと片方だけ古くなって食い違う。

渡すのは、確定した md と出力先のパスと上の指定だけ。
**委譲先の作法と、このスキルの規約が食い違ったら、このスキルの規約を採る。**
食い違った箇所と、どちらを採ったかを報告する。黙って片方に寄せない。
**委譲先が同じ機械で動くことを確かめる。** `docx` `xlsx` スキルが無い環境では
md のまま渡し、変換できないと報告する。黙って自分で書こうとしない。
